Software Requirements Specifications: Budget wise

This document outlines the software requirements for the "Budget wise" project, as per the CS251 course assignment.

1. Document Purpose and Audience

This document explains how the system will be built, covering system architecture, design decisions, components, modules, class diagrams, and technical details. It is intended for Developers, Software Architects, Technical Teams, System Designers, and Testers.

2. Architecture

The system uses a 3-Tier Layered Architecture for scalability, portability, and maintainability.

LayerComponentDescription
PresentationMobile/Web UIUser interaction, dashboards, charts.
ApplicationAuth, Transaction, Budget, Analytics, SyncCore business logic and API management.
DataRelational DBStorage of profiles, transactions, and history.

3. Class Diagram Summary

The system comprises several key entities, including User, Transaction (with Income and Expense subclasses), Category, Budget, FinancialGoal, Notification, and Report.

4. SOLID Principles Implementation

  • Single Responsibility: Models, Services, and Controllers have distinct, limited responsibilities.
  • Open/Closed: The Transaction base class is extended for new types (like Income/Expense) without modification.
  • Liskov Substitution: Income and Expense are used interchangeably where a Transaction is expected.
